# 实验协议草案

状态：尚未冻结，不是预注册；当前 demo 不能用于检验研究假设。

## 主问题

有限反馈与预算下，验证候选搜索策略是否比直接积累经验，更稳定地提高未见任务表现？

## 主环境与对照

优先考察 BrowseComp-Plus；MuSiQue 可作为开发与迁移环境。先验证下载、索引成本与官方拆分，再决定正式配置。不得将测试题用于积累经验后，报告为未见任务泛化。

计划对照：固定 ReAct、案例记忆、ACE、ReasoningBank、验证后的策略更新。所有方法固定执行模型、工具、语料和检索器。baseline 适配需记录与原实现的差异。

## 正式运行前必须填写

- 数据集版本、许可、各 split 的绝对大小、去重与实体/证据隔离规则。
- corpus 与 retriever 的版本、top-k、返回长度及工具协议。
- 模型实际标识、推理配置、温度与种子支持情况。
- 每题预算、总学习预算、记忆长度预算、更新频率。
- 反馈来自何处；标准答案、证据标签或自评分别何时可见。
- 候选策略验证规则、验证集访问上限、接受阈值及回滚规则。
- 主比较、主指标、独立运行次数、区间估计与停止条件。
- 排除、失败、超时及重试处理规则。

## 数据与评测

学习任务流、策略验证集、开发监控集、最终测试集职责分离。开发反复查看的集合不能再当作完全未见测试。公开 benchmark 可能已进入模型训练数据，应报告污染风险并设置不使用工具的能力检查。

主报告包含答案正确率、检索/打开证据召回、引用支持度、调用数及完整成本。证据 ID 命中仅是代理指标，不能声称等于语义支持。

比较同等学习经历和同等累计成本下的曲线。成本包含生成、反思、记忆检索、验证、预热及可计量的失败重试；评测费用单列。缓存命中与未命中分别保留。

重复单位为独立学习轨迹；同一轨迹的 turn 不能当独立样本。使用配对任务顺序并报告运行间波动。正式样本量根据 pilot 方差和预算确定。

## 机制实验与完整系统

固定候选集合可隔离接受规则的局部影响。在线学习中不同记忆会导致轨迹分叉，不能假定不同方法自然产生相同候选。

若声称质量不降低，提前规定可接受下降幅度并报告区间；不显著不等于等效。单题成功不能证明一条策略具有因果效用。
