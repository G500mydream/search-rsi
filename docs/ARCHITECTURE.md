# 架构与实现边界

核心边界：完成一个搜索任务，与根据这个任务更新未来策略，是两个独立过程。

```text
任务 + 冻结记忆 -> Search Agent -> 工具调用 -> 轨迹
                                         |
标签（仅评测器） ------------------------> 反馈
                                         |
                               学习器提出候选策略
                                         |
                               独立验证 / 接受或拒绝
                                         |
                                  新记忆版本
```

当前已实现上半部分的离线示例和冻结记忆。候选生成、验证、更新、恢复及真实 API 均为后续工作。

## 输入与权限边界

- `Task` 只包含 id 与 question；`Gold` 独立保存在评测侧。
- `solve` 不接收标准答案或支持文档标签。环境提供可搜索语料，这是允许访问的证据。
- `MemorySnapshot` 不可变；未来在线实验应为整个题目固定版本。
- 测试时关闭所有写入；评测反馈不得进入下一题记忆。
- Tool response 中的内容是文档数据，不应被提升为系统指令。

## 后续接口

真实模型适配器需要记录模型标识、请求时间、延迟、完整原始 usage、缓存字段、重试和失败。无 usage 的失败请求标为未知，不能记作免费。

真实搜索适配器应固定 corpus/retriever revision、top-k、截断规则、排序和文档 ID。实时 Web 后端应另行记录返回快照和时间。

学习器允许不同内部表示，不能为统一接口而删除 baseline 的核心算法。适配版与原方法的差异需显式记录。

日志从新目录开始写入，现有输出不会被覆盖。当前没有断点续跑；后续实现必须同时恢复任务序号、记忆、配置和预算账本。
